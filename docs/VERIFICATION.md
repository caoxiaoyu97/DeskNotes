# 验证记录

## 桌面挂载的重大修正

第一版把便签用 `SetParent` 挂到资源管理器桌面窗口（`Progman`）下。实测在本机 Windows 11（内部版本 26100）上这条路走不通：

- 窗口被报告为 `IsWindowVisible = true`，位于 `Progman` 子窗口最上层（`SHELLDLL_DefView` 之上），但屏幕上完全不绘制，只透出壁纸。
- WPF 与 WinForms 表现相同，因此不是 WPF 绘制方式的问题。
- 附带问题更严重：子窗口无法获得键盘焦点，便签上根本打不了字。

对照实验（同一张截图内三个窗口）：

| 方式 | 结果 |
| --- | --- |
| 顶层窗口 + `SetWindowPos(HWND_BOTTOM)` | 正常显示 |
| 顶层窗口 + 插到 `Progman` 之后 | 正常显示 |
| `SetParent` 到 `Progman` 子窗口 | 报告可见，实际不绘制 |

因此改为**不改变父子关系**：便签保持普通顶层窗口，固定到层叠顺序最底部。普通程序都在它上面，桌面在它下面，输入功能保持正常。

## 已修复：显示桌面后便签消失

现象：点任务栏右下角的「显示桌面」后便签消失。

复现（调用 shell 的 `ToggleDesktop()`，与任务栏按钮同一接口）并打印层叠顺序：

| 时刻 | 层叠顺序（上 → 下） |
| --- | --- |
| 显示桌面前 | 任务栏 → **便签** → 桌面 |
| 显示桌面后 | 任务栏 → **桌面** → 便签 |

原因：固定位置用的是 `HWND_BOTTOM`，它的含义是「整个层叠顺序的最底」。平时桌面就在最底，所以便签恰好落在桌面之上；一旦资源管理器为「显示桌面」把桌面窗口提上来，`HWND_BOTTOM` 就把便签压到桌面**下面**。此时 `IsWindowVisible` 仍返回 true，所以只靠可见性判断发现不了，窗口看起来是「消失」了。

修复：不再使用 `HWND_BOTTOM`，改为显式插入到桌面窗口正上方——取 `GetWindow(Progman, GW_HWNDPREV)`，把自己插到该窗口之后；若发现自己已经在桌面正上方则跳过，避免每 700ms 重复调整层级。

修复后验证：同一复现步骤下，显示桌面前后层叠顺序都是「任务栏 → 便签 → 桌面」，并截图确认便签在桌面上可见。

## 已知行为

- **全屏游戏会盖住便签**。全屏独占或全屏无边框程序覆盖整个桌面时便签不可见，退出全屏后自动恢复。这是固定到桌面层的必然结果。
- 便签放在别的程序常驻区域（例如编辑器窗口所在位置）时会被那个程序盖住，这是设计如此；换个空位即可。
